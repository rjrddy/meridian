# Meridian design

The difficult boundary is deciding when a sample is still allowed to change an estimate. An already displayed estimate cannot be silently rewritten when a delayed packet arrives. The C++20 single-owner engine maintains a bounded deque per stream and a monotonically advancing tick watermark. Clock calibration is an explicit reference probe, not guessed from correlated values. Samples must advance their source timestamp and arrive ahead of the committed watermark. Rejected late data and overflow are counted. Future samples are never used by an earlier tick.

At each tick, retain the newest sample at or before the watermark, reject sources older than max_age, and fuse remaining measurements by inverse variance with age inflation. A scalar random-walk Kalman filter combines that measurement with the previous state. When all sources disappear, predict without measurement: hold the mean and grow uncertainty. Before any valid measurement the state is explicitly uninitialized. This is causal zero-order hold, not lookahead interpolation. It estimates one common scalar; independent physical modalities must first be transformed into that common coordinate.

Memory is bounded by stream_count × capacity. Tick work is bounded by accumulated buffer contents; ingest is constant amortized time. The watermark advances by caller decision, so no source can block the engine. There is no hard real-time scheduler guarantee. Clock drift, adversarial spoofing, collision avoidance and certified hardware safety are outside this model. Calibration uncertainty is not modeled. Equal-clock duplicates are rejected deliberately.

The Python owner persists canonical input events and output frames in one SQLite transaction per frame batch. SQLite WAL and a single writer are appropriate for one process; multiple application workers are unsupported. A frame is broadcast only after commit. WebSocket consumers receive bounded queues with explicit skipped-frame counts; a slow viewer cannot block acquisition. Replay reconstructs a fresh engine from persisted events and compares canonical IEEE-double JSON outputs on the same build. This does not promise cross-compiler or cross-architecture bit identity.

Control-plane authentication uses a salted scrypt password hash and expiring server-side sessions. Session cookies are HttpOnly and SameSite strict, with configurable Secure for TLS deployment. Mutations require an anti-CSRF header matched to the session. Login and mutation budgets are bounded per client. Inputs are typed and size limited; this is a single-user demonstration, not an internet-scale identity service.

Proof must distinguish compute, commit and browser arrival latency. Synthetic event time is not wall-clock latency. Public sensor replay is useful for compatibility and does not supply synthetic ground truth. All figures will be generated from saved command output, never copied from the old projects.
